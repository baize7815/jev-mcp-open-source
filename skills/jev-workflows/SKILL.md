# Jev 工作流

只使用使用者明确连接或通过 `JEV_MCP_URL` 配置的服务。不得从项目作者的域名、部署记录或 Cloudflare 登录文件推导备用地址或提取授权；缺少配置时请使用者配置自己的服务。

在下列决策点主动使用已部署的 Jev MCP，不等待用户点名。选择与当前任务匹配的一个流程；不要为了增加调用次数让所有消息都经过 Jev。

## 意图与路径

当前消息存在多种合理解释、需要承接前文，或需要在多个工具/知识源之间选择时，在确定处理路径前调用 `route_intent`。传入原始 `request`、最少必要的 `context`；已有具体候选时用 `routes: [{id, description}]` 指明候选意图、工具或知识源。

例如“把刚才那个整理一下”且前文有多个对象，需要核对指代；“到我的资料里找那个教程”涉及多个知识源，需要选择检索入口。含义明确的命令直接执行。

`status=needs_review` 时，利用上下文复核 `suggested_route`，仅在缺失信息会改变任务时询问用户。`unavailable` 时按已有信息继续，不自动重试。意图结果不是用户授权，不能据此把讨论变成修改、把建议变成发布。

同一请求和相关上下文不变时复用已有结果；新消息改变目标或候选后才重新判断。

## 文件与知识库检索

先用当前可用的文件搜索或知识库工具取回候选。当多个结果需要按含义判断相关性或决定阅读顺序时，先调用 `rerank_candidates`，再读取排在前面的原文。精确且无歧义的文件命中可直接读取。

输入为 `query` 和 `candidates: [{id, title?, text}]`；`text` 要有实际摘要或片段，仅文件名不足以判断内容相关性。每批最多 10 条，总输入不超过 128 KB。跨批排序时使用相同 query，设置 `top_k: 10`，合并各批的分数排序。保留 ID 到路径/来源的映射。

失败项是未判断，不是无关；不得悄悄丢弃。分数只辅助选择证据，最终回答仍以读到的原文为准。没有候选或没有读取权限时，Jev 不能代替检索工具或补造内容。

## 批量判断

对多条记录重复分类、标注或筛选时调用 `batch_judge`，传入 `items: [{id, state}]` 和共用 `questions`。每批最多 10 条。服务端分别评估每条记录，并发上限 3；不要把所有记录塞成一个 state 后只问一个总体问题。

Choice 使用明确的命名选项；Noul 判断条件是否成立；Score 使用 2–10 个有具体含义的有序等级。独立问题可共享同一条 state。使用代码做排序、计数、阈值和权重计算。低置信度不是自动通过或自动拒绝；根据任务复核。

## 工具入口与旧连接

优先使用已连接的 Jev 服务所提供的 `route_intent`、`rerank_candidates`、`batch_judge`，保留 `system_one` 用于自定义单条判断。工具名称以客户端实际暴露的名称为准。

如果连接缓存里只有旧 `system_one`，不要编造不存在的工具名。可用本 Skill 的 `scripts/call-mcp.mjs` 直接访问同一服务，直到客户端刷新：

```powershell
node <本Skill目录>/scripts/call-mcp.mjs --describe
node <本Skill目录>/scripts/call-mcp.mjs rerank_candidates --input <候选JSON文件>
```

使用前由使用者通过环境变量 `JEV_MCP_URL` 配置自己的 MCP 地址；脚本不包含默认远程地址，未配置时会停止且不会联网。通过初始化和工具列表核对后只调用一次，不自动重试。TypeSafe API Key 仅由部署者在服务器管理。仅传递任务所需、允许发给该服务的内容，不传凭据或整段无关对话。

批量原文尽量由代码读取并组装 JSON 文件，避免将整批原文先打印进助手上下文。查看返回的 ID、计数与需复核条目即可；需要引用时再读取相关原文。

这是主动选择工具的工作流指导，不是拦截每轮消息的 Hook。若工具不可用且 HTTP 备用方式也失败，说明一次并继续独立可完成的工作。
